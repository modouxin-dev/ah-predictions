## 1. 范围与记账

- 参与者：模型 A / B / C（`model_id`），每个模型带 `model_version`；版本变更视为新样本序列（统计按 model_id 汇总，同时列出 `model_versions`，评估时按版本拆分复核）。
- 玩法：亚盘 `ah`、胜平负 `1x2`、大小球 `ou`。
- 配额：**每模型 × 每玩法 × 每天最多 3 场**（按报告日期 `date`）。按 `generated_at` 先后取前 3 场，超出的报警（logger `ah.experiment`）并**拒绝计入**，列在 `experiment_stats.json` 的 `rejected`。
- 记账：1 单位平注，**报告时刻**赔率（`odds_if_known` + `odds_format`，hk 净赔 / decimal 欧赔）。实验盘**不计入正式命中率**，不推送 Telegram，不在网站作为推荐展示。
- 文件：
  - `data/experiment_picks.csv`：与 `data/predictions.csv` 同一 v3 表头（`track=experiment`），另加评估列 `generated_at, model_p, market_p, close_line, close_odds, close_odds_opp, close_fair_p, close_captured_at`。
  - `data/experiment_stats.json`：按 模型 × 玩法 的统计（`python -m ah.audit.experiment_track stats`）。
  - 为什么不并入 predictions.csv：predictions.csv 被 settle/records/stats/build_site/tg_bot 以及定时任务读写，并入会让每个读取方都必须过滤 track，一处遗漏就会污染正式战绩；分文件后正式链路零改动。作为第二道防线，`stats.compute` 与 `records.sync_*` 仍会忽略 `track != official` 的行，`migrate_csv` 发现时会报警。

## 2. 结算口径

| 玩法 | 选项 | 结算 |
|---|---|---|
| ah | home / away，line 为所选一方视角 | 沿用正式亚盘结算（含四分之一盘） |
| ou | over / under，line 为总进球线 | 整数线可走盘；半球线只有输赢；四分之一线拆两半（赢半/输半）。例：大 2.25 进 2 球 = 输半，大 2.75 进 3 球 = 赢半，大/小 3 进 3 球 = 走 |
| 1x2 | home / draw / away | 只有赢、输 |

比分一律为 90 分钟（含补时），加时与点球不计。

## 3. 指标

- **命中率** = (赢 + 0.5×赢半) / (已结算 − 走 − 作废)；**ROI** = 盈亏 / 同一分母。
- **CLV**（与 paper_trades 同口径）：`o_bet(十进制) × p_fair − 1`，`p_fair` 为收盘去水概率（`close_fair_p`，或用 `close_odds` + `close_odds_opp` 乘法去水）。ah/ou 只在收盘盘口 = 下注盘口时计算；盘口变动时 CLV 留空，另记 `line_move`（所选方向的盘口差，正 = 拿到更好的线）。
- **Brier**：
  - ah / ou：`(model_p − y)²`，y = 赢 1 / 赢半 0.75 / 走 0.5 / 输半 0.25 / 输 0，`model_p` 为模型给出的**期望结算得分** E[y]（不是赢盘概率）。注意：paper_trades 的 Brier 目前只计整赢/整输，两者不可直接比较。
  - 1x2：**所选结果的二元 Brier** `(model_p − 1[所选结果发生])²`，`model_p` 为所选结果的概率。选二元而非三分类，是因为实验盘每行只记录所选结果，三分类需要模型输出全部三个概率；如果之后模型都能输出三个概率，再在协议 v1 升级为多类 Brier。
  - 市场基准：`market_p` 填 **market-baseline-v0** 的同口径去水概率；`brier_skill = 1 − Brier_model / Brier_market`（只用两者都有的场次），> 0 表示优于市场。
- **最大回撤**：按开球时间累计盈亏的峰谷差（单位）。
- 缺数据一律 `null`（前端显示「暂无」）。`significant` 只在 `clv_n ≥ 100` 且 CLV 95% 置信区间不含 0 时为 true。

## 4. 评估节奏

| 时间 | 主要看什么 | 可做的决定 |
|---|---|---|
| 第 1 周 | **CLV 为主**（样本少，命中率/ROI 噪声极大），检查数据完整性：收盘覆盖率、generated_at 合规、拒绝原因 | 只修数据管道，不评定模型好坏 |
| 第 2–3 周 | CLV 趋势、line_move、Brier 与市场基准对比 | 无 |
| 第 4 周 | 正式评估一次：每个 模型 × 玩法 出评估表 | 只对**已满 100 场**的组合下结论；未满的标「样本不足」继续观察 |
| 之后 | 每满 100 场滚动复评 | 升级 / 淘汰（下节） |

「满 100 场」= 该 模型 × 玩法（同一 model_version）有 CLV 的已结算场次 ≥ 100（作废、拒绝的不计）。

## 5. 升级与淘汰标准（建议阈值，待先知签字）

**升级候选**（进入正式推荐的候选池，仍需先知人工批准，且只升级具体的 模型 × 玩法 组合），须同时满足：

1. 样本 ≥ 100 场（同一 model_version）。
2. 平均 CLV > 0，且 **CLV 95% 置信区间下限 > 0**（经第 6 节多重比较校正后的置信区间）。
3. Brier 优于 market-baseline-v0：`brier_skill > 0`，有 market_p 的场次 ≥ 80。
4. 最大回撤 ≤ 15 单位（按 1 单位平注）。
5. ROI 只作参考：ROI < −5% 时需要先知书面说明理由才能升级，但 ROI 好**不能单独**作为升级依据。
6. 数据合规：拒绝率 < 5%，收盘覆盖率（有 CLV 的已结算场次 / 已结算场次）≥ 80%。

**淘汰**（满足任一）：

1. 满 100 场后 **CLV 95% 置信区间上限 < 0**。
2. 满 100 场后 `brier_skill < −0.02`（明显差于市场基准）且平均 CLV ≤ 0。
3. 最大回撤 > 25 单位。
4. 连续两次滚动复评（200 场）平均 CLV ≤ 0 且置信区间下限 < 0（长期无优势）。
5. 违反防事后修正规则（第 8 节）一次即暂停该模型，调查后由先知决定。

**观察**：其他情况继续记账，不升级也不淘汰。

## 6. 多重比较

3 个模型 × 3 种玩法 = 9 个组合同时检验，若都用 95% 置信区间，纯运气下至少一个「显著」的概率约 1 − 0.95⁹ ≈ 37%。因此：

- 升级判断使用 **Bonferroni 校正**：9 个组合时单个组合用 99.44% 置信区间（z ≈ 2.77，替代 1.96）；组合数变化时按 `α/k` 重新计算。`experiment_stats.json` 中的 `clv_ci95` 是未校正的，只用于日常观察。
- 新增模型或玩法要在协议里**事先登记**，登记前的结果不算数。
- 不允许挑选「表现好的联赛/时间段」单独报告（事后切片）；任何切片分析只作探索，结论需在新样本上重验。

## 7. 重叠场次

- 多个模型推同一场同一玩法时**各记各的**，每个模型的统计照常计入；`overlap` 列标出其他模型及方向（same/opposite），与正式推荐重叠时加 `official:same|opposite`。
- 评估时另报「去重叠」口径：只看该模型独有（overlap 为空）的场次，用来判断模型是否只是跟随其他模型或正式推荐。若某模型 > 70% 场次与正式推荐同向，其增量价值需单独论证。
- 反向重叠（A 推主、B 推客）不做抵消，两边各自结算。

## 8. 数据缺失与防事后修正

- **不补值**：缺报告时刻赔率的推荐直接拒绝（不按 0.9 估算，与正式盘不同）；缺收盘 → CLV 为 null；缺 model_p/market_p → Brier 为 null。不做插值或用其他公司赔率替代，除非事先在协议中登记。
- **生成时间早于开球**：`generated_at` 必填且必须早于 `kickoff_utc`，否则拒绝。
- **文件只追加、不覆盖**：`add_picks` 只追加新行；同一 (date, match_id, model_id, market) 只认第一条；结算只写结算列（result/ah_outcome/units/settled），推荐内容列（方向、盘口、赔率、概率、生成时间等）被改动时报错。overlap 是派生列，可以重算。
- 建议每天把 `data/experiment_picks.csv` 随日报一起提交，用 git 历史作为时间戳证据；评估时对比 git 历史，确认推荐内容在开球后没有被改过。
